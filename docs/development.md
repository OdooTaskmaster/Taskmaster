# Разработка

[README](../README.md) | [Архитектура реализации](architecture.md) | [Проверки](testing.md)

1. Найдите задачу и её критерии в GitHub issue или локальном `.private/9_github_issues.md`. Проверьте блокеры и ограничения по [AGENTS.md](../AGENTS.md).
2. Реализуйте только согласованный объём. Проверяйте API и поля Odoo на версии, зафиксированной для пилотного стенда. Не используйте старые команды установки и настройки как инструкции к новому плагину.
3. Проверьте изменение по критериям задачи. Приложите к PR фактические действия и результаты, включая ограничения, если часть проверок недоступна. Обновите документацию фактической реализации, если поменялись классы, их взаимодействия или порядок работы.

На текущем этапе установка отключена. После выполнения `TECH-01` здесь появится проверенная инструкция для пилотного стенда. В PR не включаются секреты, содержимое `.private/` и реальные проектные данные.
