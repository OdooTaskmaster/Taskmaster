# AG-01. Отчёт: выбор внешней модели для пилота

Issue: [#7](https://github.com/OdooTaskmaster/Taskmaster/issues/7) · дата оценки: 26.11.2026 · ветка `docs/ag-01-model-evaluation`

## 1. Кратко

Проверено **15 моделей**, из них 6 — на полном наборе из 10 кейсов. Все 6 прошли без
критических нарушений контракта (выдуманные источники, утечка при отказе доступа,
запрещённые упоминания). Итоговая рекомендация — **`z-ai/glm-5.3-flash`** на
российском эндпоинте; резерв для РФ-юрисдикции — **`sber/gigachat-3.5-ultra`**;
эталон качества — **`anthropic/claude-haiku-5.5`** (обработка в США).

RouterAI использовался **только как транспорт для оценки**: один ключ, один
OpenAI-совместимый API, фиксация провайдера на запрос. В итоговом плагине роутер
выбирается отдельно — решение ниже сформулировано про **модель и официального
провайдера**, а не про RouterAI.

## 2. Методика

Стенд: `tools/model_eval/`. Синтетический проект Odoo (1 проект, 2 команды,
15 задач, 36 комментариев, 6 пользователей, 5 «шумных» задач) — реальные данные
не использовались.

Модель работает по контракту T1 из согласованной архитектуры:

- **пять инструментов чтения**: `read_task_card`, `read_task_description`,
  `read_task_stage_history`, `read_task_comments`, `read_task_worklog`;
- **идентификаторы источников** вида `task:T-101`, `comment:T-101:C3`,
  `worklog:T-101`, `history:T-101`, `description:T-101`;
- **статусы ответа**: `ok`, `insufficient_data`, `access_denied`, `source_error`;
- **строгий JSON**: `answer`, `status`, `facts[]`, `sources[]`, `missing[]`.

Права проверяет сервер, а не модель: инструменты не принимают ID задачи,
пользователя или проекта. При отказе сервер возвращает `status=denied` без
названия, деталей и счётчиков.

Оценка: контракт 20, факты 35, источники 20, статус 15, русский язык 10.
Hard fail: выдуманный источник, факт с несуществующим источником, запрещённое
упоминание, утечка при `access_denied`.

Смысловая часть (формулировки, различение факта и сообщения участника) проверена
вручную по `raw.jsonl`; автоматика её не заменяет.

### 4.3 Что показали отдельные модели

- **`yandex/aliceai-llm-flash` не вызывает инструменты.** 0.3 вызова на кейс,
  на C04 и C08 — ноль вызовов и ответ «из головы». Метаданные эндпоинта не
  заявляют tools, и фактическая проверка это подтвердила. Для пилота не годится
  независимо от качества текста.
- **`openai/gpt-oss-120b` и `gpt-oss-20b`** стабильно отдают факты с пустыми
  значениями (`assignee: ""`, `deadline: ""`) и пропускают часть инструментов —
  контракт 67%. Дешёвые, но на C08 (нехватка данных) ломаются.
- **`openai/gpt-5-nano`** требует `max_completion_tokens` вместо `max_tokens`:
  иначе reasoning съедает лимит и ответ приходит пустым. После настройки качество
  нормальное, но C04 занимает 57 с — для интерактивного сценария Odoo неприемлемо.
- **`google/gemini-3.1-flash-lite`** быстрый (p50 3.4 с) и дешёвый, но на C02
  заявил отсутствие данных, хотя описание было усечено сервером. Это ровно тот
  дефект, который пилот не должен допускать.
- **`qwen/qwen3.7-flash`** лучший по цене (0.42 ₽ за прогон), но на C09 перепутал
  сбой источника с отсутствием данных — критично для разбора рисков.
- **`sber/gigachat-3.5-ultra`** надёжен в отказах доступа и статусах, но на C02
  не вызвал `read_task_description`, а на C08 выдал два факта с пустыми полями.

Выводы:

- **РФ-юрисдикция без оговорок** — только Sber (Cloud.ru) и Yandex. У GLM
  российский эндпоинт — это локальный реселлер; сам вендор обрабатывает данные в
  Сингапуре или Китае, поэтому РФ-размещение нужно подтверждать договором с
  конкретным провайдером, а не свойствами модели.
- **DeepSeek** хранит данные в КНР и допускает обучение — для данных клиник
  неприемлемо без обезличивания.
- **Claude, GPT, Gemini** — обработка в США; для персональных данных пациентов
  требует отдельного решения владельца проекта.
- **Mistral** — единственный вариант с ЕС-размещением по умолчанию
  (`api.eu.mistral.ai`), если США и КНР исключены, а РФ-качество не устраивает.

## 7. Решение

**Основная конфигурация пилота: `z-ai/glm-5.3-flash`.**

Обоснование:

1. 98.5 из 100 на полном наборе, ноль hard fail, 100% по контракту, фактам и
   источникам на девяти кейсах из десяти.
2. Единственная слабость — C08 (85): отвечает `ok` там, где данных нет. Лечится
   уточнением промпта, а не сменой модели.
3. Цена 5.95 ₽ за прогон, контекст 262k, tools и structured заявлены и работают.
4. Вендор заявляет отсутствие хранения контента; при этом РФ-размещение требует
   договора с конкретным провайдером.

**Резерв при жёстком требовании РФ-вендора: `sber/gigachat-3.5-ultra`** (93.0,
Cloud.ru, 152-ФЗ). Слабости: C02 — не читает описание, C08 — пустые значения
фактов. Обе лечатся на уровне промпта и валидации ответа.

**Эталон и запасной вариант: `anthropic/claude-haiku-5.5`** (99.0, 1.52 ₽) —
если владелец проекта допускает обработку в США.

**Не рекомендуются:** `qwen3.7-flash` (путает сбой источника с отсутствием
данных), `gemini-3.1-flash-lite` (игнорирует усечение), `aliceai-llm-flash` (не
вызывает инструменты), `deepseek` (КНР + цена), `gpt-oss` (пустые факты).

Окончательное решение подтверждает владелец проекта — DRAGONARU.

## 8. Ограничения

- Один прогон на модель: стабильность не доказана, для финалиста нужен повтор.
- 10 кейсов — мало для статистики; оценка показывает поведение на конкретных
  классах ошибок, а не среднее качество модели.
- Автоматическая оценка не проверяет стиль и смысловую точность формулировок.
- Стенд повторяет контракты T1, но не является продакшен-кодом: нет LangGraph,
  Odoo ORM, REST, брокера и реальных прав Odoo.
- Промпт общий для всех моделей; per-model настройки (`max_completion_tokens`,
  бюджет reasoning) допускались только как техническая совместимость.
- Данные синтетические; выводы по качеству на реальных задачах проекта не
  проверены.

## 9. Воспроизводимость

```powershell
python tools/model_eval/run_eval.py --self-test
python -m unittest discover -s tools/model_eval/tests -v

# Smoke: 15 моделей, 3 кейса
python tools/model_eval/run_eval.py --stage smoke --models "<id,id,...>" --run-id smoke

# Полный прогон: 10 кейсов
python tools/model_eval/run_eval.py --stage full --models "<id,id,...>" --max-cost 45 --run-id full

# Пересчёт оценок без вызовов API
python tools/model_eval/rescore.py results/<run_id> --patch results/<other_run>
```

Артефакты: `results/full-v1/` (60 записей), `results/full-v1-c09/` (перепрогон
C09), `results/smoke-final/` (45 записей), `results/smoke-v1..v6`, `results/probe*`.
В `raw.jsonl` — промпты, ответы, tool calls, usage и стоимость; ключ не пишется.

Всего израсходовано на оценку: **99.66 ₽**.
