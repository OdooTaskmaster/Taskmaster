# AG-01: сравнение внешних моделей

Стенд для выбора одной внешней модели пилота по issue
[#7](https://github.com/OdooTaskmaster/Taskmaster/issues/7). Сравнение идёт на
синтетическом проекте Odoo, а не на реальных данных. Модель получает только
разрешённый контекст и пять узких инструментов чтения.

## Что проверяется

- русский язык и краткость ответа;
- вызов инструментов и соблюдение их аргументов;
- структурированный JSON-ответ по схеме;
- разделение проверяемых фактов и сообщений участников;
- корректные источники без выдуманных ID;
- поведение при нехватке данных, отказе доступа и сбое источника;
- задержка и стоимость одного кейса.

Смысловая оценка формулировок остаётся за ревьюером: автоматика проверяет
контракт, статус, наличие ожидаемых фактов и источников, но не «красоту» текста.

## Состав

| Путь | Назначение |
|---|---|
| `run_eval.py` | CLI: смета, dry-run, self-test, запуск стадий. |
| `runner.py` | Промпт, payload, цикл tool calls, один прогон модели на кейсе. |
| `contract.py` | Разбор JSON, проверка схемы, источников и автоматическая оценка. |
| `eval_core.py` | Синтетический fixture и серверная реализация пяти инструментов. |
| `tool_schemas.py` | Схемы инструментов и итогового ответа. |
| `models.json` | 10 кандидатов, endpoint, страна, цены, возможности. |
| `cases.jsonl` | 10 кейсов, включая data gap, отказ доступа и сбой источника. |
| `fixtures/project.json` | 1 проект, 2 команды, 15 задач, 36 комментариев. |
| `tests/` | Модульные тесты без сети. |
| `results/` | Результаты прогонов; в Git попадают только по решению ревью. |

## Ключ

Ключ RouterAI читается из `ROUTERAI_API_KEY`. Файл `.env` лежит в корне плагина:

```text
custom_addons/taskmaster/.env
```

```dotenv
ROUTERAI_API_KEY=...
```

`.env` исключён из Git. Ключ не попадает в логи, `raw.jsonl`, сообщения модели
и вывод CLI. Для проверки без ключа используйте `--self-test` и `--dry-run`.

## Команды

```powershell
# Проверить стенд и контракты без сети
python tools/model_eval/run_eval.py --self-test

# Модульные тесты
python -m unittest discover -s tools/model_eval/tests -v

# Показать модели и кейсы
python tools/model_eval/run_eval.py --list

# Смета и промпт без запросов
python tools/model_eval/run_eval.py --stage smoke --dry-run

# Первый дешёвый probe: 1 модель, 1 кейс, лимит 10 руб.
python tools/model_eval/run_eval.py --stage probe

# Smoke: 10 моделей, 3 кейса, лимит 80 руб.
python tools/model_eval/run_eval.py --stage smoke

# Полный прогон только для выбранных финалистов
python tools/model_eval/run_eval.py --stage full --models sber/gigachat-3.5-ultra,deepseek/deepseek-v4.1-flash-1017 --max-cost 100
```

Полный прогон всех 10 моделей на 10 кейсах не запускается автоматически: смета
выше 100 руб. Сначала probe, затем smoke, затем 3–4 финалиста.

## Стадии и деньги

| Стадия | Модели | Кейсы | Лимит по умолчанию |
|---|---|---|---:|
| `probe` | DeepSeek V4.1 Flash, RF endpoint | C01 | 10 руб. |
| `smoke` | все 10 | C01, C04, C08 | 80 руб. |
| `full` | только `--models` | все 10 | 100 руб. |

Смета считается как 15k входных и 1.8k выходных токенов на кейс — верхняя
оценка с запасом на 3 шага чтения. Перед запуском CLI печатает смету и
останавливается, если она выше `--max-cost` (обходится только `--force`).
Во время прогона жёсткий лимит проверяется после каждого кейса. При 401/402
прогон останавливается сразу.

через `GET /api/v1/models/{author}/{model}/endpoints` 25.11.2026.

## Контракт ответа

Модель обязана вернуть JSON:

```json
{
  "answer": "краткий ответ на русском",
  "status": "ok | insufficient_data | access_denied | source_error",
  "facts": [
    {"source_id": "task:T-101", "field": "deadline", "value": "2026-11-20"}
  ],
  "sources": ["task:T-101", "comment:T-101:C3"],
  "missing": ["чего не хватает"]
}
```

Сервер проверяет:

- JSON и обязательные поля;
- `source_id` только из фактически возвращённых результатов;
- отсутствие названий и деталей закрытой задачи при `access_denied`;
- отсутствие выдуманных источников и запрещённых упоминаний;
- ожидаемый статус и ожидаемые инструменты;
- русский язык эвристикой по доле кириллицы.

Оценка: контракт 20, факты 35, источники 20, статус 15, русский 10.
Штрафы: 20 за запрещённое упоминание, 10 за выдуманный источник, 15 за утечку
при отказе доступа. Любой hard fail означает, что модель нельзя рекомендовать
без ручного разбора.

## Кейсы

| ID | Что проверяет |
|---|---|
| C01 | Карточка: срок и исполнитель. |
| C02 | Усечённое описание: нужный фрагмент за серверным лимитом. |
| C03 | История статуса: дата последнего перехода. |
| C04 | Комментарий о блокере: утверждение участника, не доказанный факт. |
| C05 | Сумма трудозатрат за период. |
| C06 | Конфликт: комментарий «согласовано» против статуса «На проверке». |
| C07 | Отказ доступа к задаче другой команды без раскрытия деталей. |
| C08 | Недостаточно данных: пустые комментарии, трудозатраты и история. |
| C09 | Сбой источника комментариев: отличить от пустоты. |
| C10 | Шум в комментариях: выбрать релевантный блокер. |

## Результаты

После запуска создаётся `results/<run_id>/`:

- `run.json` — стадия, модели, кейсы, смета, git commit;
- `raw.jsonl` — полные ответы, tool calls, usage и стоимость без ключа;
- `summary.csv` — агрегаты по моделям;
- `summary.md` — таблица для PR и ручного ревью.

Результаты smoke и финального прогона прикладываются к PR вместе с
[`REPORT.md`](REPORT.md) и [`DECISION.md`](DECISION.md). Сырые логи содержат только
синтетические данные.

## Ограничения

- Это оценка модели и выбранного endpoint, а не приёмка AG-02.
- Стенд не реализует LangGraph, Odoo ORM, REST, брокер и реальные права Odoo.
- Инструменты повторяют логические контракты T1, но не являются продакшен-кодом.
- Автоматическая оценка не заменяет смысловое ревью фактов и формулировок.
- Один прогон не доказывает стабильность модели; для финалиста нужен повтор.
